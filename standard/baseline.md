# วัดผลจริง — ก่อน/หลังใส่มาตรฐาน

> เป้าหมาย: เปลี่ยนตัวเลขประมาณใน [v1.md](v1.md) ให้เป็นข้อเท็จจริงที่ยืนยันเองได้
> ตัวเลขในเอกสารนั้นมาจากการให้เหตุผล **ยังไม่เคยวัด** — ที่นี่คือที่เก็บของจริง

---

## วิธีสลับโหมด

สิ่งที่เปลี่ยนพฤติกรรม AI คือ `CLAUDE.md` (มันอ่านไฟล์นี้ก่อนทำงานทุกครั้ง)
สคริปต์อย่าง `scope.mjs` วางอยู่เฉย ๆ ไม่มีผล ถ้าไม่มีใครบอกให้ใช้

```bash
# โหมด "ก่อน" — สภาพเดิมของโปรเจกต์
cp standard/CLAUDE.before.md CLAUDE.md

# โหมด "หลัง" — มีมาตรฐาน
git checkout -- CLAUDE.md
```

`CLAUDE.before.md` มีแค่ `@AGENTS.md` ซึ่งเป็นเนื้อเดิมก่อนเราเพิ่มอะไร
**เก็บ `AGENTS.md` ไว้ทั้งสองโหมด** เพื่อให้ตัวแปรที่ต่างกันมีตัวเดียวคือชุดมาตรฐาน

---

## กติกาการวัด — ผิดข้อเดียวตัวเลขใช้ไม่ได้

1. **งานเดียวกันเป๊ะทั้งสองรอบ** ใช้ prompt เดิมคำต่อคำ
   ถ้าเทียบงานคนละชิ้น ตัวเลขไม่มีความหมาย เพราะงานต่างกันกินโทเคนต่างกัน 5–10 เท่าอยู่แล้ว
2. **เซสชันใหม่ทุกรอบ** ปิดแล้วเปิดใหม่ ไม่งั้นรอบหลังเร็วเพราะ AI จำโครงได้ ไม่ใช่เพราะมาตรฐาน
3. **1 เซสชัน = 1 งาน** จบงานแล้วพิมพ์ `/cost` จดเลข แล้วปิด
4. **ทิ้งโค้ดหลังวัด** — `git checkout -- .` ทั้งสองรอบ นี่คือการวัด ไม่ใช่การส่งงาน
   (รอบ "ก่อน" ต้องคืน `CLAUDE.md` ด้วย)
5. **สลับลำดับบ้าง** งานที่ 1 วัดก่อน→หลัง · งานที่ 2 วัดหลัง→ก่อน
   กันผลจาก OS disk cache และความเหนื่อยของเครื่อง

---

## เลือกงานมาวัด

เลือก **3 งานจริง** ที่เป็นตัวแทนของงานที่ทีมทำบ่อย ไม่ใช่งานง่ายที่สุด:

- 1 งานแก้บั๊กเล็ก แตะไฟล์เดียว
- 1 งานแก้ที่กระทบหลายไฟล์ (นี่คือที่มาตรฐานควรได้เปรียบชัดสุด)
- 1 งานเพิ่มฟีเจอร์เล็ก

จดคำสั่งที่ใช้ไว้ให้ตรงกันทั้งสองรอบ

## ⚠️ ข้อจำกัดของการวัดชุดนี้ — เขียนกำกับไว้ก่อนใครเอาไปอ้าง

- **n = 3 น้อยมาก** พอบอกทิศทางได้ ยังไม่พอสรุปเป็นตัวเลขแม่นยำ
- **pms-app ไม่มีผู้ใช้จริง** จึงวัด "ความกลัวลดลงไหม" ไม่ได้ ซึ่งเป็นตัวเผาโทเคนที่ใหญ่ที่สุดตามที่วิเคราะห์ไว้
  → ตัวเลขที่ได้จะเป็น **ขอบล่าง** ของประโยชน์จริงบนระบบที่ส่งมอบแล้ว
- **ไม่มีครึ่ง DB** (typed client, RLS smoke) ซึ่งประเมินว่าแก้ R2 ได้ 70–85%
  → ที่วัดได้คือประสิทธิผลของครึ่งเดียว ไม่ใช่ v1 เต็ม
- ผลขึ้นกับว่า AI ทำตาม `CLAUDE.md` แค่ไหน ซึ่งต่างกันได้ตามรุ่น/การตั้งค่า

**ห้ามเอาตัวเลขจากที่นี่ไปสรุปว่ามาตรฐานคุ้มหรือไม่คุ้มสำหรับโปรเจกต์ที่มีลูกค้าใช้จริง**
อันนั้นต้องวัดบนโปรเจกต์นั้นเอง
